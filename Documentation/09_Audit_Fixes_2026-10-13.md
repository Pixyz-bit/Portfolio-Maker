# Audit fixes — 13 October 2026

The requested repairs are implemented locally. The deployed site and its existing records were not modified.

## Changes

- Portfolio saving parses and validates all section data before writing. A single SQL connection/transaction updates the profile and replaces the five sections with bulk inserts. Any validation, permission, constraint, trigger, or SQL failure prevents success and rolls back the database changes. A missing section payload is rejected; an explicit empty array can intentionally clear a section. New images are removed on failed saves, and superseded images are removed after commit.
- Portfolio and admin text bindings are encoded, JavaScript arguments receive contextual encoding, and social links require absolute HTTP/HTTPS URLs. Stored avatar paths are restricted to the upload directory.
- Visibility actions authorize the current authenticated owner/admin, read the target's state, and toggle it atomically. Signed ViewState is bound to the session. Protected pages refresh current account status/role; credential changes invalidate the old credential stamp.
- Account Settings loads the authentication email independently of the public contact email. Password/visibility failures are reported instead of silently ignored.
- Dialogs receive accessible roles/titles, opening focus, Tab containment, Escape dismissal, and restored focus. Form fields have labels, including generated onboarding rows. Focus indicators and reduced-motion behavior were added without redesigning the existing interface. Narrow wizard navigation scrolls within its container.
- The affected-row helper executes once. Stored procedures must return their documented scalar row count; text commands use ExecuteNonQuery. Failures propagate.
- Public search filters and paginates in SQL, returns 12 portfolios per page, and fetches skills only for those results. Portfolio/editor reads use one multi-result query. CSS URLs no longer use a new timestamp on every request.
- Uploads decode actual JPEG/PNG/WebP content, enforce a 2 MB input limit and 4096-pixel dimension limit, and re-encode to PNG. Filename extensions alone cannot pass validation. Existing image paths come from the database, not the hidden input.
- Login diagnostics default to off, are limited to local opt-in requests, and repository exception details are logged server-side instead of displayed to users.
- Invalid explicit portfolio links return not-found behavior. The unconditional latest-user fallback was removed.
- Password verification no longer accepts plaintext or the stored hash itself. New passwords use randomly salted PBKDF2-SHA256 with 600,000 iterations. Existing SHA-256 accounts upgrade on successful password login. Plaintext legacy entries require a password reset.

## Validation

Release compilation, ASP.NET page/control precompilation on a clean site copy, JavaScript syntax checks, 41 disposable LocalDB regression assertions, 18 local HTTP regression assertions, and browser checks passed. The database tests include a forced insert-trigger failure and confirm rollback of both profile changes and deleted section rows. HTTP checks exercise malformed and valid saves, account-email and active-status preservation, stored HTML rendering, target visibility state, SQL paging/search, invalid links, anonymous admin access, and signed-request replay after logout.

Browser checks cover dialog roles and associated labels, initial focus, Tab wrapping, Escape dismissal/focus restoration, account email, encoded portfolio content, directory pagination, generated onboarding labels, and a 392-pixel CSS viewport without page overflow. At a stress-test viewport of 255 CSS pixels, wizard navigation stays in its scroll container, but minor page overflow remains; this is below the sampled phone layout. These are targeted checks, not a full WCAG certification, load benchmark, or physical-device test.

## Deployment requirements

- Publish the updated application assembly and all changed ASPX/ASCX/JS/CSS/config assets together. Existing users must sign in again because old sessions do not carry the new credential stamp.
- The existing schema migrations for Description, Affiliations, SocialLinks, and IsPublic must already be applied. No production migration was executed during this repair.
- The application database principal needs SELECT/INSERT/UPDATE/DELETE permission on the portfolio tables used by the transactional save, in addition to existing stored-procedure execution rights. The save no longer attempts schema changes at runtime.
- WebP decoding uses Windows Imaging Component and requires a WebP codec on the hosting server. JPEG and PNG use built-in decoders. If WebP cannot be decoded on that server, the upload is rejected with instructions to use JPEG/PNG; it is never accepted without validation.
- New uploads are saved as PNG. Existing JPEG/WebP files continue to display. User-visible filenames/paths should not be treated as an API contract.

See `Tests/README.md` for repeatable checks. The original audit remains a historical record of the findings, rather than a description of the repaired code.
